# Color

Two layers. **Raw ramps** are named scales with no meaning attached. **Semantic aliases** point at
them and are redefined per theme. Components only ever reference the semantic layer — reaching for
`--ink-07` in a component is the bug this split exists to prevent.

Every value below is measured, not asserted. The hex under each swatch and every ratio in the tables
is read from the live computed style, so retuning a ramp updates these pages and can turn them red.

## The ramps

The neutral ramp is keyed to the `#0B0C0A` anchor and carries its hue (128.82) at very low chroma —
warm-neutral, deliberately not a cold grey and not blue-tinted.

### Why amber needs three tokens instead of one

This is the detail that decides whether the palette survives accessibility, so it is worth stating
plainly.

Amber as a **fill** behaves identically in both themes: `#FFB800` under near-black ink measures
11.42:1 either way. Amber as **text on the ground** does not — `#FFB800` on the light ground is
**1.57:1**, a hard failure. The instinct to pair a colored fill with white text also fails here:
light ink on amber is 1.58:1.

So the system splits the job three ways, and light mode drops each hue to a solved value:

- `--signal` — the fill. Same in both themes, always under `--signal-foreground` (near-black ink).
- `--signal-edge` — borders and focus rings. Only needs 3:1, so it can stay more saturated.
- `--signal-text` — the only one safe at prose size in both themes.

The same pattern applies to red and green. In practical terms: **amber sets marks and fills; it does
not set paragraphs.**

## Measured contrast

Text pairs are held to 4.5:1 (WCAG 1.4.3). Borders and focus rings are held to 3:1 (WCAG 1.4.11),
which is the correct threshold for something that only has to be distinguishable.

### Hairlines are exempt, and that is why `control` exists

`--hairline` sits around 1.5:1 against the ground in both themes. That is intentional and it is not
a violation: WCAG 1.4.11 governs visual information needed to _identify a component or its state_,
which a decorative divider is not.

An input's border is a different matter — it is what identifies the input as an input — so that
border must use `--control`, which is solved to 3:1 and appears in the table above. The two tokens
are not interchangeable, and picking `--hairline` for a form control is a real accessibility bug
rather than a style preference.

## Enforcement

These tables are documentation. The actual gate is `@storybook/addon-a11y` with
`parameters.a11y.test: "error"` in `.storybook/preview.tsx`, combined with two Vitest browser
projects that run every story in both themes. A contrast regression fails `pnpm check` rather than
waiting to be noticed.
